The problem

Limit gone by Wednesday?

“…within 10–15 minutes of using Sonnet.”
“…w/out even writing code - just reviewing markdown specs.”
“…would only limit out occasionally.”

Claude Code users on usage limits, as reported by The Register, January 2026.

You pay for context × steps.

Claude Code has no memory between steps. Each one sends the system prompt, every file read and every tool output so far, again. Read a 12k-token log at step 3 and a 40-step turn pays for it 37 more times.

Most of that is noise: progress bars, repeated lines, files already read, retries of a command that won't pass. Kiasi removes it before it lands in context, so both numbers stay small.

What it fixes

Install

Three steps, about a minute.

  1. Install the plugin

    In Claude Code:

    /plugin marketplace add raj-rangani/kiasi
/plugin install kiasi@kiasi

  2. Add two settings

    In the env block of ~/.claude/settings.json. Kiasi reminds you at session start if either is missing.

    "CLAUDE_CODE_AUTO_COMPACT_WINDOW": "200000",
"CLAUDE_CODE_ENABLE_FUNCTION_HOOKS": "1"

    The first is the biggest single lever: compaction happens at 200k instead of the full window. On the machine Kiasi was built on, mean context fell from about 250k to 57k tokens. The second turns on the experimental pruner and search.

  3. Restart, then work as usual

    Run /kiasi:limits setup once so the dashboard can show your plan limits. After a session or two, run /kiasi:dashboard.

Privacy

Everything stays on your machine.

No network calls

Not one. It reads your local transcripts and writes to its own folder.

No prompt text logged

Reports hold counts and sizes, never what you typed.

Localhost only

The dashboard listens on 127.0.0.1 and refuses other host names.

Nothing lost

Every cut output and refused paste is saved in full, and found again by search.

Does cutting output make Claude miss things?

Cuts keep the head and tail and leave a [kiasi kept …] or [kiasi trimmed …] marker naming the saved file with the full text. Claude reads that file by path when the cut part matters. File-reading commands (cat, sed, head, git diff, …) are never cleaned.

Data directory

All state (event log, saved pastes, outputs, notes and checkpoints, session records, gzipped report JSON, sync status) goes to ${CLAUDE_PLUGIN_DATA}, normally under ~/.claude/plugins/data/. Scripts run by hand (the dashboard, sync.py, search.py) follow a pointer the session-start hook leaves in ~/.claude/kiasi/. Nothing is ever written under the installed plugin code.

Cleanup

scripts/cleanup.py moves a saved file, gzipped, to trash/ once it and its session have both been unused for 7 days (pastes: 14); trash is deleted 7 days later. It runs in the background at session start and on sync, at most once a day. It:

  • touches only file names Kiasi itself writes, never through a symlink;
  • never touches the running session or anything used in the last 24 hours;
  • only reports, moving nothing, for the first 7 days (the Storage tab shows what it would move);
  • logs every move, delete and restore to cleanup.jsonl.

python3 scripts/cleanup.py --dry-run lists what would move, and --restore puts trashed files back. Set KIASI_CLEANUP to report, trash or off to override the default auto.

Plan limits and the status line

/kiasi:limits setup copies scripts/statusline.py to ~/.claude/kiasi/ and points statusLine in ~/.claude/settings.json at it, backing the file up once to settings.json.kiasi-bak. A status line you already had keeps running, with the Kiasi part added after it. Run setup again after a plugin update.

Keeping the dashboard up

On Linux, use a systemd user unit with ExecStart=/usr/bin/python3 <plugin root>/scripts/dashboard.py 8787 and Restart=always, enabled with systemctl --user enable --now. Then bookmark http://127.0.0.1:8787/.

Experimental: function hooks

The compaction pruner and mcp__kiasi__search use Claude Code's early-access function-hook API (2.1.282+), which may break on an engine update. Kiasi is fully useful without it: the seven classic hooks run regardless of CLAUDE_CODE_ENABLE_FUNCTION_HOOKS.

Requirements
  • Claude Code 2.1.283+
  • Python 3.8+, standard library only (tested on 3.10 and 3.11)
  • Linux (tested) or macOS (expected to work, not yet tested). Windows isn't supported.
  • Node 18+ only for the experimental function hooks
Development 
python3 -m unittest discover -s tests   # hook handlers, reports, dashboard (runs in CI)
claude plugin test .                     # hooks/*.test.ts on the real engine
claude plugin validate .                 # marketplace, manifest and hooks.json
npx -p typescript tsc --noEmit -p .      # type-check the hooks module (local only)

The type-check needs .claude-plugin/types/, which Claude Code writes the first time it loads the plugin from a folder (claude --plugin-dir /path/to/kiasi).

Uninstall

Run /kiasi:limits remove if you set up the status line, then /plugin uninstall kiasi. Claude Code deletes ${CLAUDE_PLUGIN_DATA} when the plugin is uninstalled from its last install location; pass --keep-data to keep it. Delete ~/.claude/kiasi/ yourself if you want it gone.
