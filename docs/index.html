    02The rules

    Three fixed rules. No model in the loop.

    Whatever Kiasi cuts is saved in full, and the agent is told where to find it.

    1. Rule 1

      A long test log becomes a digest

      The agent gets the errors, the start and the end. The rest waits on disk.

      2,082characters sent, not 10,000
    2. Rule 2

      A file read twice is skipped

      If the file hasn't changed, the agent is pointed at the copy it already has.

      245characters sent, not 29,029
    3. Rule 3

      A runaway turn is paused

      At 60 steps the turn pauses, the task is saved to a file, and you choose what happens next.

      60steps, then a pause

    Also in the box: your 5-hour and weekly limits in the status line, and compaction that keeps your task. Everything else is in the README →

    03Measured

    2.1×

    Less context per request. Mostly from one setting.

    The turn above is noisy on purpose. Over 30 days of real work on one developer's machine, context per request fell 2.1× against the days before Kiasi. Most of that comes from the 200k compaction window Kiasi sets on a 1M-context model. The cuts themselves kept out about 5%.

    07Questions

    Asked first.

    • Does the agent lose anything it needs?

      No. Everything Kiasi cuts is saved in full, and the agent is told the path. A skipped re-read points at the copy already in context.

    • How is this different from rtk or caveman?

      rtk shortens shell output, and caveman makes Claude write shorter replies. Kiasi also covers file reads, MCP results, web pages and pastes, and it measures itself against what Claude Code alone sends. JetBrains' paired test found most of rtk's advertised saving didn't reach the bill (their write-up). Kiasi hasn't had a paired test yet. That's next.

    • Does anything leave my machine?

      No. Kiasi has no dependencies and makes no network calls. Its reports hold counts and sizes, never what you typed.

    • What does it change in my settings?

      Two keys in ~/.claude/settings.json, the 200k compaction window and the pruner switch, plus a status line entry. /plugin uninstall kiasi@kiasi puts them back.
