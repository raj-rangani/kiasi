# Changelog

### Unreleased

- One task file per task under the project's `.kiasi/checkpoints/` folder, with goal, decisions, a checklist checked only when verified, files touched and next step. The turn-budget pause, the compaction note, the stop note and the new `/kiasi:handoff` skill all write it, and a new session (start, clear or resume) is handed it with "continue from here; re-verify before marking anything done".
- Two context notices at the prompt: at 150k tokens, "run /kiasi:handoff, then /clear: this task continues from about {floor}k"; and on return after the prompt cache has gone cold with over 100k of context. The floor is measured from the session's first reply. Session state carries `context_floor`, `context_tokens` and `last_call_at`.
- The SessionStart block is 7 lines instead of about 40. The full rules live in `rules.md` and the new `/kiasi:rules` skill loads them on demand.
- The compaction pruner keeps the last 3 exchanges word for word and reduces older ones to the prompt, a one-line outcome and a pointer to the archived exchange, once the transcript passes 200k chars. Hand-backs inside old exchanges keep their own pointer.
- The status line shows a context meter: `ctx 118k (floor 46k) · turn 12/60 1.4M · cache warm 52m · idle 3m`, amber at 150k and red at 200k, honouring `CLAUDE_CODE_PROMPT_CACHE_TTL`.
- Dashboard: median and p90 context next to the mean; sessions whose context passed 200k carry a "past 200k" badge and are counted on the Overview, with the `CLAUDE_CODE_AUTO_COMPACT_WINDOW` recommendation when the window is unset or larger; a "Context window and floor" sheet sizes what each project loads at session start (CLAUDE.md, skills, MCP tools, agents, memory) and suggests what to turn off.
- Budget tab: a "Cache and output" section counts 5 to 60 minute breaks that found the cache cold and the tokens they rewrote, with the 1-hour TTL suggestion; counts model and effort switches and their rewrite cost; and shows output and thinking per prompt by effort level, which transcripts do record.
- Report numbers dedupe assistant entries by message id and skip `<synthetic>` ones in both the lens and budget reports.
- README recommends `CLAUDE_CODE_AUTO_COMPACT_WINDOW=200000` and `CLAUDE_CODE_PROMPT_CACHE_TTL=1h`.
- The shared temp checklist folder is now per user (`kiasi-<user>`) and private (mode 700), so other users on a shared machine cannot read or guess it.
- Cleanup now removes saved pause records once they are older than 14 days, the same age after which a resume ignores them. A record a resume can still use is kept.
- Sandbox outputs from a session with no id are covered by the cleanup patterns and are tested.
- A failed `run` is now logged as failed and no longer counts as saved tokens in the report.
- Saving session state now retries briefly when Windows has the file open, and removes a leftover temp file from a crashed write.
- A saved file that a subagent read, or that a Kiasi search returned, now counts as read back, so its cut is no longer credited as saved.
- The Sessions tab marks a session resumed from an earlier day with "resumed, earlier part not shown", since only its part inside the window is counted.
- A report write no longer fails on Windows when another program holds the file open for a moment; it is retried a few times first.

- At compaction, a long tool result is no longer left uncut just because its last line starts with `[kiasi `; only the markers Kiasi itself writes count.
- When a long tool result is cut, every saved-file pointer line in the dropped part is kept (up to five), not just the first.
- Searching for a bare `--` now finds lines containing it.
## 0.4.2 - 2026-10-07

- After a pause, parallel refused calls now count as one refused response even before Claude Code has sent a tool batch, so a pause in the first response no longer ends the turn early.
- The status line now locks its limits files on Windows too, so two sessions no longer log the same reading twice there.
- The Rules tab has a Problems block, shown only when something went wrong: pauses that could not be saved, lock timeouts and ignored `.kiasi.json` values, each with a plain explanation, a count and the last message.
- Subagent reports that arrive as an agent message or inside a system notice are now kept whole or archived at compaction, like task notifications. When no archive can be written, a long report keeps its first part and ends with a line saying how much was trimmed, instead of being cut to a few lines with no pointer.
## 0.4.1 - 2026-10-07

- The status line script changed (a lock around its limits files). It is a copy under the data folder, so run `/kiasi:limits setup` again after updating to get it.
- Parallel refused calls in one response count as one refused response, so a pause no longer ends the turn early. The third refused response still ends it.
- The checklist written at the budget warning is the one a later stop, subagent brief or "continue" points at. It used to name the next free file, which did not exist.
- Several sessions in one project can be paused at the same time; each keeps its own resume record (one file per session, old single records still read). A pause can be resumed only once.
- Cleanup no longer removes the state or checklist of a session whose pause record is still live, so "continue" after a week still resumes.
- A pause that cannot be written to disk is logged as an error and the budget still trips; the session state is saved before the record.
- Identical reads in one response are all skipped, not just the first. A running subagent keeps its step count when the next prompt arrives, and a late batch for a cleared turn adds no step.
- Session state, the daily history, the savings file and sync status are written to a temp file and renamed, so an overlapping dashboard build can no longer read a half-written file and shrink the history to the current window.
- A bad value in `.kiasi.json` (such as `1e999`) falls back to that setting's default and is logged once, instead of silently switching off every hook in the project. A lock wait that gives up is logged too.
- Checklists fall back to the system temp folder when the project is not writable; the old fallback under `~/.claude` is a path Claude Code refuses to write.
- Compaction keeps a background subagent's hand-back report recoverable (whole up to the normal size, archived beyond it) instead of cutting it to 200 chars with no archive. Other injected messages are archived too.
- Compaction recognises every Kiasi digest marker, so a tool output Kiasi already capped is not cut again; when a cut is unavoidable the pointer to the saved file is kept. Large strings inside nested tool inputs such as MultiEdit edits are shrunk like top-level ones.
- Compaction archives are named per agent with a random suffix, never overwrite an earlier file, and a marker is only written when the archive write succeeded.
- `mcp__kiasi__search` matches quoted phrases as phrases, and words starting with "-" work. `mcp__kiasi__run` flags a failing command as an error. The quiet npm/pip flag rewrite leaves quoted text alone.
- Dashboard: a session resumed today no longer adds its old steps and bill to today; Budget and Overview bucket by the same local day (the stored history is recounted once from the oldest surviving transcript day); report windows are whole local days and per-day rule bars use untruncated counts.
- Dashboard: delegation is credited only when the Agent call was allowed or a subagent transcript started after it; "repeat reviews questioned" is counted again; a skipped read that was retried, or a capped output that was read back, saves nothing; a subagent's skipped read is credited by its own steps.
- Dashboard: days with no new session or no prompts show a dash instead of "0 k" and "−100%"; the steps-per-day and 300-step figures are main-session only; the top steps band follows the configured budget; the Turn budget rule shows what was chosen at the pause question; the other logged events appear in the counts.
- Dashboard: a deleted transcript or a bad line no longer fails the whole build (skips are counted and shown); data older than two rebuild intervals is marked stale; a rebuild stuck in "running" is treated as failed and the banner names its start time.
- Fixed: the outside-read cap and the Storage log on Windows paths; a notification title with `&` or `<`; cleanup of leftover compact and unknown-session output files.

## 0.4.0 - 2026-10-07

- The dashboard counts what the rules did over whole days. Rule events were counted over the last 168 hours while the token bill was counted by calendar day, so the first day of a period showed its bill but none, or only part, of what the rules did that day.
- The same question is put at the warning, before the pause: Claude follows the warning and so seldom reaches the pause, and used to choose between ending the turn and a subagent itself. Continue there renews the budget; stop or a subagent pauses the turn at that point, so replying continue later resumes it.
- At a pause Claude now asks how to go on, where it used to only end the turn: continue here with a fresh budget, hand the rest to a subagent, or stop. The checklist is written first, and Kiasi reads the answer. Continue renews the budget in place; the other two leave the turn paused, so replying continue later still resumes it. The question is asked in the terminal, the VS Code extension and the desktop app; a headless run and a subagent are paused as before. `pause_question` (auto, always or off; also in `.kiasi.json`) sets it.
- A desktop notification when Kiasi pauses a turn, and when it ends one after refused calls, in the VS Code extension and the desktop app. Their chat shows the pause as one grey line, which is easy to miss in a background window. It uses `notify-send` on Linux, `osascript` on macOS and a PowerShell toast on Windows; the terminal keeps its own notification and bell. The new `pause_notification` setting (auto, always, off) says where it shows.
- The turn budget counts steps, not tool calls. The tool calls Claude makes in one response are one step: the next request re-reads the context once for all of them. Each call used to count on its own and add the whole context to the re-read total, so a turn that worked in parallel reached its budget early. Kiasi counts at Claude Code's `PostToolBatch` hook, which runs once per response. Until the first one arrives in a session the calls count one by one, and that batch gives the extra counts back. A batch of calls that were all refused at the pause is not a step. Subagent budgets count the same way. The notices, the session rules and the subagent briefs say "steps" and say that parallel calls count once.
- Dashboard: a delegation saving is credited only when an Agent call followed the instruction before the next prompt. It was credited whenever the instruction was shown, whether or not Claude delegated. An instruction that was not followed is listed with the checks shown, as "delegate, no Agent call".
- Dashboard: "Avoidable misses" no longer counts a cache that expired while the session was idle; those misses are shown beside it. The extra cost still covers them, since they were paid for.
- Dashboard: the "each step costs N× less than before" headline waits for 300 steps both before and after the install, and until then says how many there are. It used to show a factor after a few dozen steps.
- When the dashboard's sync reaches its timeout, the report scripts it started are stopped with it. Only the sync itself was stopped, so a hung report script kept running.
- When Claude keeps calling tools after a pause and Kiasi ends the turn, the developer is told so in a system message: "Kiasi ended this turn: Claude kept calling tools after the pause", with both ways to resume. VS Code does not show a hook's stop reason, so the turn ended there after three refused calls with no explanation.
- On Windows, a dashboard that an older version left running is replaced at the next session start. It had been started with no console, so it kept opening an empty window at every 30-minute rebuild until it was stopped by hand. Like the rest of the Windows support, this is untested on a real Windows machine.
- `tests/e2e_parallel_compact.py` resumes the session once more after the compaction and checks the batch again.
- Turn checklists are written to `.kiasi/checkpoints/` in the project, a folder that git ignores. Claude Code refuses Claude's writes anywhere under `~/.claude` as edits to a sensitive file, so a checklist in Kiasi's data folder was never saved in headless runs, and sessions that accept edits got a permission prompt at the pause. A session without a writable project folder still uses the data folder. Search and the state restored after compaction look in both. The daily cleanup moves idle project checklists to trash like the ones in the data folder, finding their folders through the turn events, which now name the checklist path; a restore puts them back in their project, and the storage tab counts them.
- A pause in a turn resumed with "continue" keeps the task and edited files of the pause it resumed, so resuming it again without a checklist still has them. A new task prompt drops them.
- The turn budget has a mode, `turn_budget_mode`: `pause` (the default) pauses the turn as before, `warn` only warns, before and at the budget, and refuses nothing, and `off` only counts calls. Subagent budgets, the session rules, subagent briefs and the status line follow it. The token budget is a setting too (`turn_token_budget`, 8M by default), and `.kiasi.json` can also set `turn_warn_tokens`. The session rules now state the configured budgets instead of the defaults.
- Replying "continue" after a pause resumes it. Kiasi adds the saved checklist (up to 2,000 characters) to that prompt, asks Claude to check `git status` first and to keep each item open until it is verified, and shows "Kiasi: resuming from <path>". After `/clear`, or in a new session of the same project, the session start says that work is waiting, and the first "continue" there resumes it the same way. Any other first prompt is only told where the checklist is. If Claude never wrote the checklist, the resume starts from the paused turn's task and the files it edited. The pause notice now says to reply "continue" after `/clear` as well.
- The turn budget warning now comes 10 calls before the pause (at 50 of 60) or at 80% of the token limit, instead of at 30 calls or half the tokens, so a turn keeps its working room. It says about how many calls are left, counting the tokens a wide context re-reads, and asks Claude to finish the item in progress and keep the checklist current. A subagent is warned 10 calls before its own limit (30 of 40). `turn_warn_steps` in `.kiasi.json` still sets the warning outright.
- When a paused turn ends and Claude's last message does not name the checklist, the Stop hook asks Claude once to close with the pause line. Hook messages may not show in the desktop app or VS Code, but Claude's reply does. The reminder is hook context, not a Stop block, so it never shows as an error, and it is skipped when the refused calls have already ended the turn.
- A turn that reaches its budget is paused instead of blocked. The developer gets a notice with the cause, where the remaining work is saved and both ways to resume (reply "continue", or `/clear` and resume from the checklist), plus a desktop notification and a bell; the warning at 30 calls is shown to the developer too. Every call except Write and Agent is refused before it runs, and the third refused call ends the turn with the same notice. A paused subagent has its calls refused as well, but never ends the developer's turn. Before, the stop was a PostToolUse block: the call had already run, nothing was stopped, and the terminal showed a hook error, so the chat looked dead.
- A subagent is held to its own budget of 40 tool calls, the figure its brief already gave it: it is warned at 20 and stopped at 40. Nothing enforced that figure, and since subagents got their own count they ran to the main turn's 60. At the stop it is told to write its checklist and reply to its caller, since a subagent cannot start another subagent. The new `subagent_call_budget` option sets the figure; `turn_call_budget` no longer changes it. The dashboard leaves subagent warnings and stops out of the turn-budget figures, and the budget report counts them on their own lines.
- A session's hooks no longer overwrite each other's turn counts. Each hook loads the session's state, changes it and saves it, and parallel tool calls and subagents run their hooks at the same time, so one save could drop the calls another hook had just counted, and the turn budget fired late or not at all. A hook now holds the session's lock file, `sessions/<session id>.lock`, while it runs, on Windows too. It waits at most 3 seconds for the lock, then goes ahead without it, so a hook never hangs a tool call. Cleanup removes the lock file with the rest of the session's state.
- On Windows, the dashboard counts saved outputs, pastes and checklists that were read back. It looked for `outputs/`, `pastes/` and `checkpoints/` with a forward slash, which a Windows path never contains, so Recall showed none read back and marked every row "could be tighter", and Storage counted every saved file as unread.
- The before-and-after table shows "–" for re-read tokens per day until a full day has passed since the install. It showed 0 and −100% on the first day after it.
- A subagent's tool calls count toward its own turn budget, not the turn that started it. Claude Code sends a subagent's calls with the main session's transcript path, so they were added to the parent turn's call count and measured at the parent's context size: parallel subagents used up the parent's budget, and once a turn was stopped the general-purpose subagent its stop message hands the checklist to was told the budget was exhausted within its first five calls. Turns are now keyed by `agent_id`, a subagent's re-read size comes from its own transcript, and a new prompt starts every count afresh.
- On Windows, the dashboard no longer opens an empty terminal window every 30 minutes. The server was started with no console at all (`DETACHED_PROCESS`), so each 30-minute rebuild, which starts `python sync.py`, made Windows give it a new visible console window, titled with the Python path and empty because the output goes to the log. Detached processes now get a hidden console that everything they start inherits. A dashboard that is already running keeps opening windows until it is stopped once.
- The sandbox tools no longer fail at their longest timeout. Claude Code's `process.run` takes at most 600000 ms, and `run`, `distill` and `fetch` asked for their timeout plus 10 seconds of headroom, so `timeout_s: 600` asked for 610000 ms: the hook threw and the call failed with "no tool.call hook answered this call". The longest timeout is now 590 seconds, derived from the host limit (`PROCESS_RUN_MAX_TIMEOUT_MS`), and the tool schemas advertise it.
- Compaction shortens a text that only mentions its marker. A text was left whole whenever it contained `[kiasi pruned` anywhere, so a large tool result showing Kiasi's own source, its tests or a transcript was never shortened at any compaction. Only a text whose last line is a marker, which is how an earlier compaction leaves it, is now kept as it is.
- A second compaction keeps the sizes the first one wrote. The pruner replaces the content of older Write, Edit and NotebookEdit calls with its size, such as `[9000 chars]`, and the next compaction measured that marker as if it were the content, so `[9000 chars]` became `[12 chars]`. A value that is already a size marker is now kept as it is.
- Every turn checklist goes to a new file. Claude Code refuses to overwrite a file outside the working directory without a read record, and a hook compaction clears those records and restores none. After a compaction, a stop or reminder that named the turn's existing checklist got "File has not been read yet", and the stop rules out the Read that would get past it. `checkpoint_path` now names the next free `<session>-<turn>-<n>.md` once the turn's file exists, and cleanup matches the numbered names.
- Compaction keeps every result of parallel tool calls. Claude Code writes a parallel batch as one assistant entry per call, sharing one message id, and the pruner rebuilt each entry as its own message with a fresh id, so the batch loaded as separate messages and every call but the last came back as `[Tool result missing due to internal error]`; on the maintainer's machine that hit 46 of 61 compactions in 7 days and lost 488 results, mostly web searches, Bash and fetches. `hooks/prune.js` now rebuilds each batch as one message ahead of all its results, also when a result was written between two of its calls, and the recent messages it keeps unchanged never start inside a batch. New tests in `hooks/compact.test.ts` cover the layouts Claude Code writes, and `tests/e2e_parallel_compact.py` replays the case against a real session (about eight Haiku calls).

Section headings now put the figure label across both columns and top-align the lede with the heading. The limit cap line at the end of the simulator rails is gone.

The launcher reads `plugin-root` and `data-dir` from `~/.claude/kiasi`, both recorded at every session start, so it survives plugin updates. The session-start hook keeps starting the dashboard when nothing answers, so a session alone is still enough.

## 0.3.0 - 2026-10-01

- First-cost avoidance: two new sandbox tools (needs `CLAUDE_CODE_ENABLE_FUNCTION_HOOKS=1`). `mcp__kiasi__run` runs a shell command, saves the full output under `outputs/` (searchable like any other saved output) and returns only a digest: exit code, head, error lines from the trimmed middle, tail and the saved path. `mcp__kiasi__distill` runs a short python3 or node script over file paths and returns only what the script prints (capped at 4,000 chars; the overflow is saved and named) — counting, filtering or parsing a big file no longer means reading it into context even once. Both in `scripts/sandbox.py` behind `hooks/sandbox.js`; `rules.md` routes bulk commands and file analysis to them.
- Search results name the hit line numbers (`path (score) lines 12, 87, 310 +2 more`), so the follow-up read is a section around the hits, never the whole file. The search tool description says so.
- Cleanup knows the sandbox file names (`run-*.txt`, `distill-*.txt` under `outputs/`), so they age out like other saved outputs.
- Every long Bash output is capped, not just bulk commands: over 12,000 chars the model sees the head, error lines from the trimmed middle and the tail, plus a pointer to the saved full text; output that looks failed (stderr or a non-zero exit) keeps its failure lines, so the error always survives the cut. Logged as a cap of kind `bash`; `.kiasi.json` key `bash_cap_chars` tunes the threshold.
- The session postmortem flags sessions with three or more capped command outputs and points them at `mcp__kiasi__run`, where only a digest ever enters the conversation.

Logged as a cap of kind `mcp`.
