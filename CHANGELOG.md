# Changelog

### Unreleased

- On Windows, the dashboard counts saved outputs, pastes and checklists that were read back. It looked for `outputs/`, `pastes/` and `checkpoints/` with a forward slash, which a Windows path never contains, so Recall showed none read back and marked every row "could be tighter", and Storage counted every saved file as unread.
- The before-and-after table shows "–" for re-read tokens per day until a full day has passed since the install. It showed 0 and −100% on the first day after it.
- A subagent's tool calls count toward its own turn budget, not the turn that started it. Claude Code sends a subagent's calls with the main session's transcript path, so they were added to the parent turn's call count and measured at the parent's context size: parallel subagents used up the parent's budget, and once a turn was stopped the general-purpose subagent its stop message hands the checklist to was told the budget was exhausted within its first five calls. Turns are now keyed by `agent_id`, a subagent's re-read size comes from its own transcript, and a new prompt starts every count afresh.
- On Windows, the dashboard no longer opens an empty terminal window every 30 minutes. The server was started with no console at all (`DETACHED_PROCESS`), so each 30-minute rebuild, which starts `python sync.py`, made Windows give it a new visible console window, titled with the Python path and empty because the output goes to the log. Detached processes now get a hidden console that everything they start inherits. A dashboard that is already running keeps opening windows until it is stopped once.
- The sandbox tools no longer fail at their longest timeout. Claude Code's `process.run` takes at most 600000 ms, and `run`, `distill` and `fetch` asked for their timeout plus 10 seconds of headroom, so `timeout_s: 600` asked for 610000 ms: the hook threw and the call failed with "no tool.call hook answered this call". The longest timeout is now 590 seconds, derived from the host limit (`PROCESS_RUN_MAX_TIMEOUT_MS`), and the tool schemas advertise it.
- Compaction shortens a text that only mentions its marker. A text was left whole whenever it contained `[kiasi pruned` anywhere, so a large tool result showing Kiasi's own source, its tests or a transcript was never shortened at any compaction. Only a text whose last line is a marker, which is how an earlier compaction leaves it, is now kept as it is.
- A second compaction keeps the sizes the first one wrote. The pruner replaces the content of older Write, Edit and NotebookEdit calls with its size, such as `[9000 chars]`, and the next compaction measured that marker as if it were the content, so `[9000 chars]` became `[12 chars]`. A value that is already a size marker is now kept as it is.
- Every turn checklist goes to a new file. Claude Code refuses to overwrite a file outside the working directory without a read record, and a hook compaction clears those records and restores none. After a compaction, a stop or reminder that named the turn's existing checklist got "File has not been read yet", and the stop rules out the Read that would get past it. `checkpoint_path` now names the next free `<session>-<turn>-<n>.md` once the turn's file exists, and cleanup matches the numbered names.
- Compaction keeps every result of parallel tool calls. Claude Code writes a parallel batch as one assistant entry per call, sharing one message id, and the pruner rebuilt each entry as its own message with a fresh id, so the batch loaded as separate messages and every call but the last came back as `[Tool result missing due to internal error]`; on the maintainer's machine that hit 46 of 61 compactions in 7 days and lost 488 results, mostly web searches, Bash and fetches. `hooks/prune.js` now rebuilds each batch as one message ahead of all its results, also when a result was written between two of its calls, and the recent messages it keeps unchanged never start inside a batch. New tests in `hooks/compact.test.ts` cover the layouts Claude Code writes, and `tests/e2e_parallel_compact.py` replays the case against a real session (about eight Haiku calls).
- Landing page: a new Fig. 04 "the everyday" section between the rules and the dashboard, with a status line mock (ctx, turn, 5h, wk with reset time and pace, kiasi −kept) and a legend, then six cards for the status line, run, distill, fetch and search, the login-time dashboard autostart and cleanup; later figures renumbered. Section headings now put the figure label across both columns and top-align the lede with the heading. The limit cap line at the end of the simulator rails is gone.
- Windows support (untested on a real Windows machine): every hook command runs through `scripts/run.sh`, which picks `py -3`, `python` or `python3`, so the hard-coded `python3` is gone from hooks.json, the skills and the status line command (which now records the interpreter that ran setup); the function hooks try `python3`, `python` and `py -3` in turn; cleanup takes its lock with `msvcrt` where `fcntl` is missing and bails out from a timer thread where `SIGALRM` is missing; the dashboard and cleanup detach with `DETACHED_PROCESS` on Windows instead of `start_new_session`, which Windows ignored, so they no longer die with the session that started them.
- `/kiasi:dashboard autostart on|off|status`: the dashboard can run from login with no Claude Code session at all. `on` writes a small launcher to `~/.claude/kiasi` and registers it with the system's login starter: a systemd user service on Linux (XDG autostart where there is no user systemd), a LaunchAgent on macOS, a script in the Startup folder on Windows. The launcher reads `plugin-root` and `data-dir` from `~/.claude/kiasi`, both recorded at every session start, so it survives plugin updates. The session-start hook keeps starting the dashboard when nothing answers, so a session alone is still enough.
- Landing page: everything below the hero re-imagined as six figures: an interactive week-on-your-plan simulator (light/typical/heavy, two rails racing to the limit), one tool output collapsing live from 38k to 2.1k chars, a rules marquee with six hook cards, a tilting dashboard screenshot, a three-step install beside a terminal that types itself with a copy button, a trust row and a closing command box. No external requests. The install terminal has a Terminal tab and a VS Code tab: the VS Code extension has no `/plugin` command, so that tab carries the extension's `vscode://anthropic.claude-code/install-plugin` link as a button, the `/plugins` dialog path, and a copy-link button. README quick start gains the same link and the `claude plugin` shell commands.
- README rewritten to match the landing page: small logo, one number-led paragraph, key features, quick start, how it works, dashboard, privacy, settings, requirements. Landing page cost section gained presets, a per-step strip for each scenario, animated counts and a savings badge; the install section is a timeline that lights up on scroll with timed steps, an animated copy tick and a what-happens-next row.
- Landing page (docs/index.html) rebuilt around one story: hero with an animated session demo, a re-read cost calculator, six leaks and rules, dashboard proof, three-step install, privacy, and a collapsed reference. Same palette, no external requests. Dashboard screenshot refreshed.
- Per-day history: budget.py merges every build into `history.json` in the data dir, so days outlive the report window and Claude Code's transcript retention; the Overview before-and-after block reads it and no longer disappears a week after install. Report window `BUDGET_DAYS` raised from 7 to 30 days and used by the dashboard's rebuild too.

- Restructured the plugin layout, no behaviour change: `scripts/kiasi.py` is now a thin hook dispatcher over the `scripts/core/` package (constants, events, transcript, caps, prompt, turn, reads, session, launch); the report builders moved to `scripts/reports/` (`budget.py`, `lens.py`, `sync.py`); `limits.py` is `statusline_install.py` and `usage_limits.py` is `limits_data.py`; the slash commands became skills under `skills/` (still `/kiasi:dashboard`, `/kiasi:sync`, `/kiasi:limits`); the five redirect stubs in `dashboard/` are gone; `SHIPPING.md` moved to `docs/dev-notes.md`; `tests/test_kiasi.py` is split into one test file per module with a shared `tests/helpers.py`; `scripts/README.md` describes the scripts.
- Dashboard starts itself: the SessionStart hook probes `127.0.0.1:8787` (and the port recorded in the data directory's `dashboard.json`) and, when no Kiasi dashboard answers, starts `dashboard.py` detached in its own session, so it outlives the Claude Code process and keeps the 30-minute rebuild running. Before this, nothing in the plugin started the server: `/kiasi:dashboard` ran it as a background shell that died with the session, so on any machine without a hand-made systemd unit the pages went dark after the session ended and the auto-rebuild never fired. `/kiasi:dashboard` now runs `dashboard.py --ensure` (same probe, returns at once with the URL). `KIASI_DASHBOARD=off` disables the autostart. The server also rebuilds the reports on start when they are missing or older than 30 minutes, records pid and port in `dashboard.json`, logs only failed requests to `dashboard.log` (truncated past 200 KB), and sends a `Server: kiasi-dashboard` header the probe recognises. The dashboard status line now says "last rebuild failed" with the error from `sync.json` instead of silently showing an old build time, and two stale error texts in `sync.js` that still named `sync.php` are gone.
- Sandbox routing: while the sandbox tools are registered (`CLAUDE_CODE_ENABLE_FUNCTION_HOOKS=1`), a PreToolUse hook on Bash and WebFetch refuses a raw call once and names the sandbox call to make instead — `mcp__kiasi__run` for a command whose output would only be scanned (tests, builds, installs, lint, curl, git log, docker logs, long tails; a command that already limits its output with `| head`, `-5`, `--oneline` or a redirect stays raw), `mcp__kiasi__fetch` for a page. The identical call repeated goes through, like the big-file Read nudge. Events `routed` and `route_retry` show in the dashboard under a new Sandbox routing rule, so compliance is visible. Context-mode reports this blocking step as the difference between prompting alone (~60% compliance) and routing (~98%); four days of this install's logs showed the sandbox tools used zero times with prompting alone.
- New sandbox tool `mcp__kiasi__fetch`: downloads a URL, strips HTML to text, saves the whole page under `outputs/` (searchable, cleaned up like other saved outputs) and returns only the first 3,000 chars plus the lines matching the `find` words, with line numbers. Its saving is logged as a cap like the other sandbox tools.
- Dashboard empty states: a tab with nothing to show no longer renders its headings over blank charts. Before the first report exists each tab explains what it will show and offers a "Build the report" button that runs the sync; a report with no session in range says so and offers "Rebuild now"; the plan-limits strip stays visible on the Budget tab. Copy lives in `EMPTY_STATES` in `lens-constants.js`, the renderer in `lens-common.js`. The per-section "No … in range yet" lines share one wording.
- First-cost avoidance: two new sandbox tools (needs `CLAUDE_CODE_ENABLE_FUNCTION_HOOKS=1`). `mcp__kiasi__run` runs a shell command, saves the full output under `outputs/` (searchable like any other saved output) and returns only a digest: exit code, head, error lines from the trimmed middle, tail and the saved path. `mcp__kiasi__distill` runs a short python3 or node script over file paths and returns only what the script prints (capped at 4,000 chars; the overflow is saved and named) — counting, filtering or parsing a big file no longer means reading it into context even once. Both in `scripts/sandbox.py` behind `hooks/sandbox.js`; `rules.md` routes bulk commands and file analysis to them.
- Search results name the hit line numbers (`path (score) lines 12, 87, 310 +2 more`), so the follow-up read is a section around the hits, never the whole file. The search tool description says so.
- Cleanup knows the sandbox file names (`run-*.txt`, `distill-*.txt` under `outputs/`), so they age out like other saved outputs.
- Every long Bash output is capped, not just bulk commands: over 12,000 chars the model sees the head, error lines from the trimmed middle and the tail, plus a pointer to the saved full text; output that looks failed (stderr or a non-zero exit) keeps its failure lines, so the error always survives the cut. Logged as a cap of kind `bash`; `.kiasi.json` key `bash_cap_chars` tunes the threshold.
- The session postmortem flags sessions with three or more capped command outputs and points them at `mcp__kiasi__run`, where only a digest ever enters the conversation.
- MCP tool outputs are capped: any `mcp__*` result over 8,000 chars (except kiasi's own tools) is saved in full under `outputs/` and enters the conversation as the first 6,000 chars plus a `[kiasi kept …]` pointer — the guarantee Read, WebFetch and bulk Bash already had, now covering Playwright snapshots, GitHub lists and every other MCP server. Logged as a cap of kind `mcp`.
- Whole-file Reads of big files are nudged once: a Read with no offset or limit of a file over 30,000 chars is denied with a pointer to sectioned reads or `mcp__kiasi__distill`; repeating the same Read goes through. Images, PDFs and notebooks are exempt. Logged as `read_nudge`.
- Sandbox savings are measured: each `mcp__kiasi__run` and `mcp__kiasi__distill` call logs a cap event of kind `sandbox` (for distill, the saving counted is the Read it replaced), so the dashboard's savings totals and per-rule rows include them.
- Per-project overrides: a `.kiasi.json` at the project root tunes caps and budgets for that codebase — keys `output_cap_chars`, `mcp_cap_chars`, `web_cap_chars`, `read_nudge_chars`, `paste_refusal_chars`, `turn_call_budget`, `turn_warn_steps`, `subagent_call_budget`. It wins over the env knobs (more specific); unknown keys and non-positive values are ignored, and a broken file changes nothing.
- CI runs the whole surface: the Python suite plus the benchmark as a smoke test, and a second job that installs Claude Code and runs `claude plugin validate` and `claude plugin test`.
- Reproducible benchmark: `python3 scripts/benchmark.py` replays six shape-realistic tool outputs (Playwright snapshot, GitHub issue list, npm install log, transcript read, test run, big-JSON count) through the real handlers and prints measured reductions (81–99%); `--write` rewrites BENCHMARK.md. Nothing touches a real data dir.
- Session postmortem: the dashboard's session detail gains "What cost the most" — up to five deterministic findings ranked by token cost (single-step context jumps, heavy startup context, budget-length turns, mid-task compactions, nudged reads let through, retry loops), each with the rule that avoids it. Computed by `postmortem()` in lens.py from data already collected; nothing new is logged.
- Burn-rate forecast: the status line records every changed plan-limit reading to `limits-history.jsonl` (pruned to two weeks), and both the dashboard and the status line project when the window runs out at the current pace — the dashboard pace line gains "at this pace runs out <time>, before the reset" and the weekly status-line gauge a ✖ run-out clock, shown only when at least four hours of history predict a run-out before the reset.

- README cut to the logo, one line, the install commands and links to the website; screenshot, badges and license section removed (the MIT `LICENSE` file stays).
- Website rewritten around the pain points: where the limit leaks and the rule that plugs each, an animated session example, a context × steps chart, one dashboard screenshot, three install steps, and small motion (scroll reveals, hover states, copy feedback) that turns off under reduced motion. `docs/rules.webp` and `docs/session-detail.webp` removed.
- Website at https://raj-rangani.github.io/kiasi/ (`docs/index.html`, served by GitHub Pages from `/docs`): rules, dashboard tour, install steps, privacy and the full reference.
- README trimmed to the pitch, quick start and a link to the website, with the new Kiasi logo (`docs/logo-light.svg`, `docs/logo-dark.svg`).
- README rewritten for first-time visitors: quick start, a table of every rule, the commands, and dashboard screenshots (`docs/`, fictional sample data).

## 0.2.0 - 2026-09-30

- Dashboard server answers only requests whose Host is 127.0.0.1 or localhost (a page on another site cannot reach it through DNS rebinding), and runs `POST /sync` only when the Origin or Referer is the dashboard itself.
- Tests for the report maths: one step per request id in budget.py and lens.py, subagent billing, the day window, compaction detection, typed prompts vs tool results, weighted period means and the before-and-after factor; lens and budget are checked to agree.
- `/kiasi:limits setup|remove|status` installs the Kiasi status line (the only source of the plan limits on the dashboard), keeps any status line you had running before it, backs up `settings.json` once, and restores the previous status line on remove. The dashboard's empty limits hint points to it.
- The type-check runs from the repository root with `allowJs`, so it checks the hooks module against the JS it imports; two type errors in `hooks/compact.test.ts` fixed. It runs locally only: `.claude-plugin/types/` (the early-access declarations Claude Code writes when it loads the plugin) is no longer committed, so CI runs the Python tests alone.
- Removed `scripts/ankush.py`, an unused copy of `scripts/kiasi.py` left from the rename; stale systemd wording removed from the Sync button.
- `SHIPPING.md` (internal notes) is no longer part of the published repository.


- Loop check: a new `PostToolUseFailure` hook counts failed tool calls toward the turn budget (they were not counted before) and tells Claude to stop retrying when the same call fails 3 times in a turn, or the same command fails 5 times with different arguments. Logged as `loop`.
- State after compaction: when a session restarts from a compaction, Kiasi re-injects the task, edited files, commands still failing at their last attempt, saved outputs and checklists, read from the transcript. Logged as `state`.
- Output cleaning: build, install, test, search and other bulk Bash output, and any output with colour codes or progress bars, has colour codes and `\r` redraws removed and runs of 3+ identical lines collapsed before any cap. File-reading commands (`cat`, `sed`, `head`, `git diff`, …) are never touched. The original is saved; a cleaning-only cut is a cap of kind `clean`.
- Dashboard: figures that come from a formula carry an "est." tag with the formula as tooltip; the Rules tab has a Loop check card.

- Renamed from Ankush to Kiasi (Swahili: measure, moderation). Commands are now `/kiasi:dashboard` and `/kiasi:sync`, the search tool is `mcp__kiasi__search`, and markers read `[kiasi kept …]`, `[kiasi trimmed …]`, `[kiasi pruned …]`. On first run the old data directory is moved to the new name and a link is left at the old path, so markers already in past transcripts still open their saved files.

- The detail panel is now a proper modal drawer: the page behind it cannot scroll (with no sideways shift), it is inert to keyboard and screen readers, focus moves to the panel and returns to the opener on close, Tab cycles inside the panel, Escape and the backdrop close it, and reduced-motion preferences are honoured.
- Previous and next buttons (and the arrow keys) step through rules or sessions without closing the panel; a sticky row of section chips jumps within the panel and tracks scrolling.

- Compact detail panel: narrower, smaller type and tighter spacing so a rule or session detail fits with less scrolling.
- Thin, quiet scrollbars everywhere, a stable scrollbar gutter, and no body scroll lock when the panel opens, so the page never shifts sideways.

- Rule and session details open in a slide-over panel from the right (a full-screen sheet on phones) instead of expanding inline below the cards. Close with the button, Escape, the backdrop, or a tab change; the hash still deep-links to an open panel.

- Rule cards open a detail sheet: fired per day (bars, with the tokens avoided that day above each), the evidence table for that rule (tools capped and cut sizes; every compaction the pruner handled; every warning and stop with compliance; every re-read check; every paste), and the rule's log with a filter and the raw record behind each row. Deep link `/#rules/<key>`.
- Session detail is fuller: facts, seven headline numbers, a taller trajectory chart, a bill split by prompt band (under the warning / warned / stopped), a prompts table (start time, context at start, steps, cost bar, warned or stopped) folded past 20 rows, and every Kiasi action in the session with its raw record on click. lens.py now writes `prompt_rows` per session (prompt text is never logged).

- Sessions, Rules and Actions rethought. Sessions drops its stat row and shows the eight costliest sessions plus a compact table (steps, mean context, compactions, avoided, bill). Rules is now one card per rule (output cap, compaction pruner, turn budget, re-read check, paste manager, notes and recall) with fired count, tokens avoided, a one-line fact and a log link that opens that rule's events with the raw record behind each row; the steps-per-prompt chart stays. The Actions tab is gone; `/#actions` opens Rules.

- Budget fix: budget.py counted every transcript line of a model response (one per content block) as a step, so its steps, re-read totals and per-day bill were about double. It now keeps one entry per request id like lens.py, and filters steps by day rather than by transcript file age, so Budget and Overview agree.
- Dashboard renamed to plain "Kiasi". Overview drops the per-mechanism day chart and the latest-actions list, and hides bookkeeping rows in the mechanism table. Sessions hides the detail sheet until a session is picked and folds sessions under 5 steps behind a link. Rules folds compactions from before the plugin was loaded behind a link. Actions hides notes, recalls and subagent model rows until "bookkeeping rows" is ticked. Budget now has three sections: re-read per day, by project (full width, with steps and share) and biggest single outputs (full width, session column, paths shortened with ellipsis); the session table and the actions card it duplicated are gone.

- The dashboard is one page. `dashboard/index.html` holds all five views (Overview, Sessions, Rules, Actions, Budget); tabs switch by URL hash (`/#sessions`, `/#sessions/<id>`) without a reload, both reports load once and every view renders from the same data, and Sync refreshes all views together. The old `<view>.html` files redirect to their tab. View scripts register through `registerView(name, render, source)` in `assets/lens-common.js`.

- Overview opens with a before-and-after block: context re-sent per step, mean context, turns over 200 k and re-read per day, for the days before Kiasi was switched on against the days after, with the implied factor by which the weekly limit lasts longer. Built from budget.json's per-day rows and the first logged event.
- The daily bill chart marks the install day.
- Glossary for "re-read" and "avoided" in the Overview tagline; friendlier empty state before the first report.
- Hand-run scripts follow the data-dir pointer the SessionStart hook writes, so the dashboard and the hooks share one directory.

## 0.1.0 - 2026-09-28

First shippable release, split out of the context-governor prototype.

- Six classic hooks (UserPromptSubmit, PreToolUse, PostToolUse, PreCompact, Stop, SessionStart) ship as `hooks/hooks.json`, running `scripts/kiasi.py` at `${CLAUDE_PLUGIN_ROOT}`.
- All state (events log, sessions, pastes, outputs, notes, checkpoints, reports, sync status, search index) moved out of the plugin root to `${CLAUDE_PLUGIN_DATA}` (falls back to `~/.claude/kiasi/` when unset).
- SessionStart injects the context rules as `additionalContext` (`rules.md`) instead of requiring them in the user's `CLAUDE.md`, plus a warning when `CLAUDE_CODE_AUTO_COMPACT_WINDOW` or `CLAUDE_CODE_ENABLE_FUNCTION_HOOKS` is unset.
- Experimental function-hook module (`hooks/kiasi.js`) provides a deterministic compaction pruner and the `mcp__kiasi__search` tool, gated behind `CLAUDE_CODE_ENABLE_FUNCTION_HOOKS=1`.
- Local dashboard (`scripts/dashboard.py`, stdlib only) replaces the old Apache + PHP + systemd sync path: serves the report pages, `/reports/<file>` JSON, and `POST /sync`.
- `commands/dashboard.md` and `commands/sync.md` slash commands.
- Python (`tests/test_kiasi.py`) and TypeScript (`hooks/compact.test.ts`) test suites; GitHub Actions CI.
- Renamed throughout: `governor` to `kiasi`, `[governor kept/trimmed]` to `[kiasi kept/trimmed]`, `mcp__context-governor__search` to `mcp__kiasi__search`, `governor.jsonl` to `kiasi.jsonl`.
